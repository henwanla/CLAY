# 为什么选 SwiftUI + Mihomo

调研于 2026-11-23。依据如下上游固定源码。

| 实现 | 如何运行 | CLAY 采用的部分 |
| --- | --- | --- |
| [V2RayU](https://github.com/yanue/V2rayU/tree/2cbeb6777ba5feab50954537ff0bde73cee34ad7) | Swift 菜单应用。节点保存在 UserDefaults；生成 config.json；通过 launchctl 管理 yanue.v2rayu.v2ray-core LaunchAgent，执行内核的 run -config config.json，源码兼容 V2Ray/Xray。系统代理由 V2rayUTool 处理，PAC 由本地 HTTP 服务提供。依据 [V2rayLaunch.swift](https://github.com/yanue/V2rayU/blob/2cbeb6777ba5feab50954537ff0bde73cee34ad7/V2rayU/V2rayLaunch.swift) 和 [V2rayServer.swift](https://github.com/yanue/V2rayU/blob/2cbeb6777ba5feab50954537ff0bde73cee34ad7/V2rayU/V2rayServer.swift)。 | 采用分享链接与本地出站导入；独立代理模式不会改动现有客户端的 LaunchAgent、PAC 或系统代理。 |
| [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev/tree/c83f7ad529c7c9cb3d2d54a0955ef8c1b22a411b) | Tauri 2 + Rust 管理配置和代理生命周期；内核是 Mihomo。在服务模式和子进程模式之间切换，系统代理与 PAC 由独立模块管理。依据 [生命周期](https://github.com/clash-verge-rev/clash-verge-rev/blob/c83f7ad529c7c9cb3d2d54a0955ef8c1b22a411b/src-tauri/src/core/manager/lifecycle.rs) 和 [系统代理模块](https://github.com/clash-verge-rev/clash-verge-rev/blob/c83f7ad529c7c9cb3d2d54a0955ef8c1b22a411b/src-tauri/src/core/sysopt.rs)。 | 用原生 SwiftUI 实现左侧导航、节点列表、切换和诊断。 |
| [V2Fly](https://github.com/v2fly/v2ray-core) / [Xray](https://github.com/XTLS/Xray-core) | V2Ray 是项目名称；VMess/VLESS 是具体协议，TCP/WS/gRPC 是传输，TLS/REALITY 是安全层。 | 一个 Mihomo 内核执行两类节点；Xray 用来搭建隔离回环测试服务端。 |

路径：应用手动配置代理 → CLAY 的 127.0.0.1 混合端口 → Mihomo 选择组 → VMess/VLESS 节点。SwiftUI 使用带 Bearer 认证的 [Mihomo 控制接口](https://github.com/MetaCubeX/mihomo/blob/v1.19.34/hub/route/server.go)。导入只映射出站，随后由 CLAY 生成运行配置，原始配置里的入站、规则和 TUN 不执行。独立代理模式不写网络设置，也无需维护两个运行内核。

兼容性记录：Mihomo 使用 YAML 解析器；JSON 生成时斜线必须保持原样，避免 WS 路径因斜线转义解析失败。每一组协议、传输、安全层均应单测；配置能解析不证明握手成功。

2026-11-24 增量：主窗口和状态栏共用一个代理会话。关闭窗口不会结束应用；正常退出统一停止 CLAY 启动的 Mihomo。订阅下载只发生在添加或手动刷新时；刷新失败会保留上一份可用缓存。运行中的会话沿用启动时的节点列表，订阅变更等会话停止后应用，避免刷新时断开当前连接。

Clash/Mihomo YAML 使用 Yams 6.1.0 随附的 libyaml C 源码解析。只读取顶层 `proxies` 列表里的 VMess/VLESS；代理提供者、代理组、规则和其他配置不会导入，不会让 Mihomo 运行订阅原文。使用 YAML 锚点、别名或自定义标签的节点不支持。依赖版本和许可证随包保存。

## 0.3.0：PAC 分流与原生仪表

- **分流层**：CLAY 从自己的规则生成 PAC，由回环 HTTP 地址提供。运行路径为「遵循 PAC 的应用 → 核对目标 → 直连或进入 CLAY 的 HTTP 混合端口」。回环目标始终直连；第一条显式规则优先于可选的本地/私网直连，其后采用所选默认策略。IPv4 和 IPv6 的 CIDR 均只处理目标地址，不为网段规则执行 DNS 查询。编辑器预览和实际 PAC 脚本使用同一套匹配顺序。不会下载或运行订阅中附带的规则脚本。
- **系统设置**：独立代理和本机 PAC 不写系统配置。用户选择系统 PAC 后，CLAY 用 SystemConfiguration 改动所选网络服务，先保存原始代理字段，用恢复记录判断是否仍由 CLAY 管理。更新 PAC 时先启动新地址，再替换系统设置。正常停用、退出或明确恢复时保留其他工具后来设置的值。异常退出重开后提示恢复，具体权限和真实服务切换留给桌面验收。
- **流量仪表**：用内置 Swift Charts 绘制近期上传和下载速度，请求 Mihomo 回环接口之前带上本次会话的认证令牌。通过单调时钟和累计字节差算速率；总量和活跃连接由内核统计。连接页可检索目标、规则和代理链，并经同一个回环接口关闭连接。PAC 直连不经过内核，因此不会出现在内核仪表里。接口不对局域网开放。
- **发行边界**：CLAY 原创代码采用 MIT；Yams/libyaml 保留各自的 MIT 声明。V2RayU（LGPL v3）和 Clash Verge Rev（GPL v3）是功能调研参考，未复制其客户端代码、素材或品牌。GitHub 的 Apple Silicon 预览包没有 Mihomo，需要依照官方发布单独安装；本机预览中的 Mihomo v1.19.34 是未修改的独立依赖，附 GPL 许可证及固定源码入口。见 [打包及发布](RELEASING.md)。
