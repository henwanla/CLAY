# CLAY 验收记录

## 开发版 · iOS 指定 IPv4/TCP 实验端点

- 宿主测试使用两个回环 VLESS 上游，经实验桥连接一个非默认的合成端点。错误地址或端口未触发上游连接；在线切换节点和模式以后，相同端点收到新上游的应答，旧上游关闭。与目标相同的字面节点地址被拒绝，正在运行的节点仍保持连接。
- Swift 验证输入、双向数据包筛选与端点读回格式。地址与端口仅随手动启动传递，界面显示扩展确认的实际端点；自定义端点不发送内置探测标记。iOS 仅请求一条 IPv4 /32 路由，没有默认路由、DNS 设置或 IPv6 接管。宿主测试不代表签名真机验证。

## 开发版 · Windows 与 Linux 节点选择器

- 主窗口显示本地配置和订阅中的节点名称、协议及导入编号。同名节点也可用编号区分；选择、启动和运行中切换继续使用同一编号。Linux D-Bus 托盘维持编号，Windows 托盘维持编号和协议。常规 CLI 预览继续脱敏。
- 桌面子进程只在输入和输出都是管道时返回显示名称。测试覆盖中日文、表情、方向控制符、长度截断和链接式名称的编号回退，并验证标准输入或输出重定向到文件时拒绝返回名称。节点名称不作为启动参数，不添加新缓存或日志。

## 开发版 · TUIC v5

- 共享导入覆盖分享链接（冒号或百分号编码分隔 UUID 与密码）、Base64 列表和内联 Clash YAML／JSON。兼容 SNI、ALPN、拥塞控制和两种 UDP 中继；拒绝 TUIC v4 令牌、关闭证书校验或 SNI、开启 0-RTT 的配置。便携命令的检查只输出协议分类，不输出地址、原名称、UUID 或密码。
- macOS 使用 Mihomo v1.19.34 回环上游实测两种 TUIC 配置的 HTTP 与 SOCKS 转发，错误指纹被拒；测试前后系统代理未变化。iOS 宿主桥以独立回环上游验证两种中继的 IPv4 TCP 与 UDP，拒绝错误口令、错误指纹和无固定指纹的自签名证书。Lab 另在同一会话在线切到两种 TUIC 节点，并按节点收到不同 TCP 应答。未使用真实订阅、节点或公网目标；移动设备上的 TUIC 数据通路尚未验收。
- iOS Lab 切换或停止时会关闭旧 TUIC 路由的 QUIC 套接字，防止 Mihomo 的连接池在空闲时继续连接旧上游。回环检查确认取消旧路由会唤醒原有读操作，并拒绝旧路由再打开套接字。

## 开发版 · iOS 隧道实验在线切换

- 同一 IPv4 测试会话中切换 VMess、VLESS、Shadowsocks AEAD、Trojan TLS 与普通／Salamander／Gecko Hysteria2 节点，新的 TCP 流收到对应合成标记。旧 VLESS 上游套接字在切换时关闭；畸形配置、直连模式和错误会话标识不替换运行节点。
- 宿主 Swift 验证 IPC 长度、版本、重放及过期标识，C ABI 验证启动、更新与停止。中／英／日界面在用户点「应用」并收到确认后才报成功。选中的配置只经系统消息发送到本应用的扩展。
- 仅测试单一 IPv4/TCP 目标，不更改系统默认路由或 DNS。尚未在签名 iPhone 上验收消息通道、后台和系统 VPN 生命周期。

## 开发版 · Android 会话节点列表

- Relay 和 VPN 共享节点选择器，按同一份 Swift 导入顺序显示本地名称、协议和传输。活动会话使用自己的节点快照，编辑或切换订阅来源只会重置下次启动的选择。节点名称仅用于应用内，选择对话框加截屏保护；普通预览、通知和快捷设置磁贴仍不显示名称或地址。
- Android 15 ARM64 无窗口测试从受保护的列表选择模拟节点，通过不同回环应答确认实际路由。覆盖 Relay 缓存切到手动输入、VPN 修改草稿后切换运行节点、无效旧选择清除，及低权限离线版的原有脱敏预览。

## 开发版 · Android VPN 快捷设置

- VPN APK 增加中／英／日快捷设置磁贴，普通 Relay 和离线 APK 不声明该入口。未连接时打开应用选择配置；活动时可以在解锁后停止当前会话。磁贴只展示可用动作，没有节点、订阅或地址信息。
- Android 15 ARM64 无窗口模拟器验证服务由系统权限保护、旧停止请求在新会话中失效、当前请求停止后台 VPN 并清除 TUN 路由。此前台流程同时跑过系统授权取消、节点切换及模式切换的真实流量、通知停止、内核退出、撤销授权和重新接入。未操作系统下拉面板或锁屏，也未验收实体设备。

## 开发版 · iOS 包转发桥与 Trojan 证书指纹

- Go 宿主回归从合成 Clash 配置经 Swift 导入再向包转发桥送 IPv4 包。分别通过七组本机上游验证 TCP：VMess、VLESS、Shadowsocks AEAD、Trojan TLS、普通／Salamander／Gecko Hysteria2；除 Shadowsocks 夹具外另外验证 UDP。这组通用桥测试在不同节点之间重启会话，并交替使用规则和全局模式。
- Trojan 的内联配置接受显式 SHA-256 证书指纹，仍拒绝跳过验证。回环验证正确指纹可连，错误指纹、无指纹的自签名证书及错误口令不能取得应答。Hysteria2 错误指纹也验证失败。夹具不访问订阅站、真实节点或系统代理；所测范围为宿主桥，不等同于 iPhone VPN 真机验证。

## 0.3.2 macOS 系统代理

- Apple Silicon / macOS 15.7.2，用固定指纹的 Mihomo v1.19.34、合成节点和本机 HTTP 源站通过工作区检查。「连接 macOS」提供将非本地请求交给内核的 PAC，即使自定义 PAC 的默认动作设为直连。HTTP 和 SOCKS5 监听可用；内核规则、全局和直连切换无需重新写系统代理设置，端口不变。模式和节点切换读回控制器确认。
- 模拟设置覆盖授权拒绝、恢复前保留监听、自定义 PAC 与「跟随流量模式」互切、系统还在使用旧 URL 时保留已发布的两个地址、系统更新后重试和结束会话时清理。验证没有改写本机实际网络设置，没有访问真实订阅或公网节点。用户浏览器与实际授权提示仍待复测。

## 开发版 · 桌面节点与模式切换（2026-11-27）

- macOS 使用固定哈希的 Mihomo v1.19.34 和回环夹具。修复前，一条 Direct 下打开的 HTTP CONNECT 隧道在切到 Global 后仍可保持连接。修复后，测试验证切模式与切换两个 VLESS 节点时原 TCP 隧道结束，监听地址不变，换节点后的新连接返回新节点的标记。重复选择当前节点或模式可继续使用原隧道。
- Linux 和 Windows 的原生控制器用例另覆盖写请求后读回、连接清理失败后不给成功回复、刷新时重试清理，以及重复选择不写配置。系统 PAC 和手动代理入口保持原样；不经过 Mihomo 的连接不在清理范围内。

## 开发版 · Android VPN 域名规则（2026-11-27）

- Android 15 ARM64 模拟器把两个合成域名解析到同一个 IPv4。旧版将应走代理的 HTTP 请求错走直连；修复后两轮回归均验证 HTTP Host、TLS SNI 分别将两个域名送往所选 VLESS 节点与直连。代理夹具只接受原目的 IPv4 和端口。
- 只在 VPN 规则模式且配置了域名规则时读取支持端口上的协议标头，不解密 TLS、不改写目的地址、不劫持 DNS。复验同时覆盖节点切换、全局／直连、授权取消和撤销、内核退出与路由清理。QUIC、Private DNS、加密 DNS、网络切换和真机仍未验收。

## 开发版 · Android 15 VPN 生命周期与路由

- API 35 ARM64 无窗口模拟器。系统授权请求取消后不启动 VPN。预授权后使用两个合成 VLESS 节点验证 IPv4 TCP、规则／全局／直连、关闭界面后继续转发、通知停止、重启和应用内停止。
- 同一 UDP A 查询经两个 VLESS 节点分别得到不同合成回答。IPv6 TCP 回环夹具在接管前后均可达，在全局和直连模式下都不能旁路。仅验证了指定 DNS 地址、明文 UDP 与局部 IPv6 路径；不代表系统自动解析、Private DNS、加密 DNS 或真机网络已验收。
- 强制终止 CLAY 自己的内核，或由独立测试包调用 Android VPN API 触发实际撤销。两组都确认内核退出、通知和临时文件清理、系统路由收回，普通网络恢复。测试包不含联网权限，不建立第二条隧道。复验命令见 [Android VPN 技术预览](../Platforms/Android/README.md#vpn-技术预览--vpn-technical-preview)。

## 开发版 · Android VPN 出站保护实验

- Android API 24 ARM64 无窗口模拟器。相同的 TUN 路由都包含客户端目标及上游地址。关保护会重现绕回；服务拒绝后，内核返回拒绝错误且没有拨号；开启逐套接字保护后，从合成 HTTP 节点拿到本轮随机响应。发往虚拟 DNS 地址的 UDP A 查询也得到本机合成解析器的预期回答。
- TUN 和出站套接字描述符使用已验证对端的私有 Unix 通道传递。内核不在未收到成功回执时拨号。测试包含显式拒绝和每次退出收回路由；没有测试实际撤销、进程故障、IPv6、现代 Android 前台服务或真实设备。没有访问真实订阅、节点或公开解析器。仍不发布全设备 VPN。

## 开发版 · Android VPN 数据通路实验

- Apple Silicon 无窗口 API 24 ARM64 模拟器。固定的官方 Mihomo v1.19.34 可以接收 Android 授权的 TUN 描述符，但读系统包名表被拒，未开启监听。用源码构建的复验内核只在已有 TUN 描述符且关闭内核自动路由时跳过该读取。
- 客户端目标由 Android 路由接管、节点地址在接管范围之外时，普通 TCP 客户端经合成 HTTP 节点收到随机标记。若将节点地址也加入接管范围，内核自己的连接进入 TUN 并被实验规则拒绝。会话退出后检查临时路由已清除。单独测试排除应用 UID 时仍多次发生绕回，未验收避环方案。只运行合成流量，没有使用真实订阅、真实节点或公网目标。
- 复验命令和源码见 [Android VPN 实验](../Platforms/Android/vpn-lab/README.md)。实验不改正常 APK；系统授权界面、前台服务、撤销、DNS、UDP、IPv6、断线行为、移动网络切换和实体机均未验收。

## 开发版 · Android 本机代理

- Apple Silicon 上的 Android API 24 ARM64 无窗口模拟器：独立离线包和 Relay 调试包均通过 Instrumentation。Relay 用单独的本机 Mihomo Shadowsocks 服务和 HTTP 源站，仅使用合成凭据。无凭据或错误凭据被拒绝，HTTP 代理认证头没有传到源站；启动检查也验证了 SOCKS5 用户名和密码握手。
- 直连、全局和规则模式均实测实际 HTTP 流量。全局用可用节点经 Shadowsocks 转发，切换到不可用节点无直连回退，规则模式保留回环绕过。换节点和模式保持监听地址不变；停止后端口和私有运行目录清理。
- 两个包应用 ID 独立。构建检查 16 KiB 对齐、调试签名、离线包无权限和 Relay 仅有联网权限。未验收实体设备、API 35 上的生命周期、全设备 VPN、后台常驻或其他协议的 Android 数据面。未发布含 Mihomo 的 Android 包。

- 使用 Mihomo v1.19.34 在本机回环和合成证书下确认普通、Salamander、Gecko 三种配置能实际转发 HTTP 和 SOCKS 请求；不匹配的证书指纹被拒绝，没有回退到直连。同期五类 VMess／VLESS 回归通过，测试前后系统代理未变化。未访问真实订阅或公网节点。

- Apple Silicon Release 构建与核心检查通过。使用固定指纹的 Mihomo、本机回环与模拟网络服务，验证了「连接 macOS」冷启动、复用手动会话、授权被拒后保留本机代理，以及停止时先恢复原代理设置，再关闭 PAC 和 Mihomo 监听。单独覆盖了 macOS 恢复状态尚未更新时保留监听和恢复记录。

## 0.3.0 · 2026-11-24

- Apple Silicon / macOS 15.7.2：Release 构建和核心检查通过。PAC 预览与 JavaScript 的动作一致；macOS 原生 PAC 解析器验证直连、HTTP/HTTPS 代理与国际化域名。
- 本机 PAC 只服务回环上的随机地址。夹具验证脚本内容、缓存响应头、请求方式、路径和请求头大小限制。应用模型在真实运行的合成内核上提供 PAC，停止时撤下地址和代理监听。
- 系统 PAC 使用模拟网络服务验证选择、备份后写入、原样恢复、尊重外部修改，以及写入、更新或恢复中断后的重试。未实际改写本机网络服务。
- 订阅导入、下载与刷新回归通过；成功刷新和 HTTP 503 失败均不会中断当前代理监听。没有窗口时，应用模型能发现自有内核退出。历史访问目的地不写入磁盘或诊断报告。
- 用 Mihomo v1.19.34 和模拟 Xray 验证五类 VMess/VLESS 转发。上传和下载累计量、测得速率、活动连接详情、关闭单条及全部连接均通过。错误凭据没有回落到直连。测试前后实际 macOS 系统代理状态相同。
- 本机 App 与公开 ZIP 均通过签名检查。解压后复核了 macOS 13.0 部署目标、arm64、版本 0.3.0、SHA-256 和三份许可；ZIP 中没有内核或真实配置。

桌面验收仍需在用户许可下进行：用真实网络服务启用并恢复系统 PAC，检查授权提示和浏览器分流；强制结束内核后从 PAC 页恢复；关闭主窗口并通过菜单栏操作，检查图表的实际呈现。公开安装包使用本机临时签名，未做 Developer ID 签名与公证。

1. 添加两份格式受支持的订阅，分别刷新；错误响应不应清空上次成功的节点。退出并重开 CLAY，检查订阅和已缓存节点仍在。
