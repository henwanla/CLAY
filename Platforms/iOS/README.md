# CLAY iOS 配置检查

这个预览应用把 CLAY 的节点解析器带到 iPhone 和 iPad。粘贴节点分享链接、Base64 链接列表、内联节点形式的 Clash/Mihomo YAML 或 JSON，或 V2Ray/Xray JSON 出站，即可看到可解析的节点数量、协议分布和问题类别。也可以用内置示例验证：结果应显示一个兼容的 VLESS 节点和一项不支持的协议。

检查在设备上进行，文本最多 2 MiB，结果只显示汇总。粘贴的内容不会写入应用文件；点「清除输入」会清空输入和结果。离线目标不下载订阅，不执行分流规则或提供器，不启动代理或 VPN，也不判断节点能否连通。界面随系统语言提供简体中文、英文和日文。

在 macOS 安装完整 Xcode 和 iOS Simulator SDK 后，可从仓库根目录构建：

```sh
xcodebuild -project Platforms/iOS/CLAY.xcodeproj -scheme CLAY \
  -configuration Debug -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

最低系统版本为 iOS/iPadOS 16。仓库附带 iOS Simulator 构建工作流；其构建产物用于开发验证，没有签名、真机安装或商店分发流程。

## IPv4 包转发实验 / Experimental IPv4 packet bridge

`Engine/` 提供 Packet Tunnel 实验使用的转发库。离线目标 `app.clay.offline` 不链接它。桥接只接收 CLAYCore 生成的节点和规则，拒绝原始配置、不认识的字段和 IPv6 包。它不开放代理／控制监听，不保存节点资料，也不输出内核日志。规则按 CLAY 现有顺序生成；模式和节点目前仅能在会话启动时选择。

The bridge is separate from the offline app. It accepts only the normalized node list and rules generated by CLAYCore. It opens no local proxy or controller, writes no profile, and suppresses engine logging. Each session accepts raw IPv4 packets. Mode and node selection take effect at start; this is not live switching.

在 macOS 上用 Go 1.24.3 和 [固定的 Mihomo v1.19.34 源归档](https://codeload.github.com/MetaCubeX/mihomo/tar.gz/refs/tags/v1.19.34) 复验（脚本检查 SHA-256）：

```sh
engine=Platforms/iOS/Engine
archive=/path/to/mihomo-v1.19.34.tgz
out="$(mktemp -d)"
bash "$engine/build.sh" "$archive" host-test "$out"
bash "$engine/build.sh" "$archive" macos "$out"
bash "$engine/link-check.sh" macos "$out"
bash scripts/swift-local.sh build -c release --product CLAYCoreChecks
.build/release/CLAYCoreChecks --packet-fixture | "$out/abi-smoke"
```

Go 回归用回环合成节点验证 IPv4 TCP、VLESS XUDP、全局节点选择、IP 规则和重启；C 链接测试检查拒绝无效参数、会话和 Swift 生成的五种节点配置。解析成功不表示五种协议已实测连通，也未验证直连流量、域名规则、DNS 或 VPN 退出时的网络恢复。GitHub 使用两个 iOS SDK 分别检查 ARM64 链接，未启动设备或安装 VPN。

CI checks arm64 linkage for both iOS SDKs. Before distributing a binary, include the corresponding Mihomo source, bridge source, build instructions, and required license files.

## CLAY 隧道实验 / CLAY Tunnel Lab

另一个 Xcode scheme `CLAYTunnelLab` 打包自己的 Packet Tunnel 扩展，与离线 App 分开。界面支持中文、英文和日文，可粘贴、导入和选择测试节点，以规则或全局模式开始，读取系统 VPN 状态，发送固定测试请求并停止。切节点或模式需要先停止。系统 VPN 的授权提示以设备显示为准，启用本实验可能暂停其他 VPN。

系统只加入 `198.51.100.42/32` 测试路由，扩展还会拒绝不符合地址、TCP 端口 `18080` 或包格式的流量。没有默认路由、DNS 覆盖、IPv6 路由或按需启动。系统 VPN 配置只保存本实验的扩展标识和固定标签，所选节点仅随启动选项发送，应用不把输入写入文件或日志。此功能用于接入验收，不能当作全设备 VPN。

The separate scheme embeds a Packet Tunnel extension with a single documentation IPv4 route. Only unfragmented TCP for `198.51.100.42:18080` is admitted. It leaves DNS and default routes alone. Node credentials are sent only with a user-initiated start, never saved in VPN preferences by CLAY. The app reports system status and sends a separate probe when asked. It requires stopping before changing node or mode.

有完整 Xcode 时，从仓库根目录构建未签名的设备目标。模拟器将两个 SDK 参数分别换成 `iphonesimulator` 和 `generic/platform=iOS Simulator`：

```sh
engine=Platforms/iOS/Engine
archive=/path/to/mihomo-v1.19.34.tgz
out="$(mktemp -d)"
bash "$engine/build.sh" "$archive" iphoneos "$out"
xcodebuild -project Platforms/iOS/CLAY.xcodeproj -scheme CLAYTunnelLab \
  -configuration Debug -destination 'generic/platform=iOS' ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO CLAY_PACKET_ENGINE_DIR="$out" build
```

真机验证 / Device validation:

1. 给 App 和扩展使用同一个开发团队，在两个标识上启用 Packet Tunnel entitlement。必要时用 `CLAY_LAB_ID` 改为该团队可签名的包名，扩展会自动带上 `.provider`。使用签名构建安装到自有测试设备；CI 的未签名产物不能安装。
2. 在可信局域网运行 `python3 Platforms/iOS/TunnelLab/synthetic-upstream.py --bind <本机私有 IPv4>`。它生成临时 VLESS 测试链接，仅响应固定测试请求，不转发流量。粘贴它到 Lab，导入、选择、启动并按设备提示授权。不要使用真实订阅来跑这项验收。
3. 系统显示已连接后点「发送测试包」，需收到测试应答。分别复验规则、全局、停止、重启、拒绝和撤销权限。退出时关闭夹具。在确认真机的路由、DNS、IPv6、后台生命周期及内存前，不应增加默认路由。

Use signing profiles that entitle the app and extension on the same team. On a trusted LAN, run the fixture with the Mac's private IPv4 address and import its temporary link in the Lab. Start the VPN, authorize it on the device, and tap “Send test packet.” A connected status alone is not a successful test. Stop the VPN and fixture when finished. Unsigned CI builds check packaging only; they do not prove that an iPhone can run the tunnel.
