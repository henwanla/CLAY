# CLAY 验收记录

## 0.3.2 macOS 系统代理

- Apple Silicon / macOS 15.7.2，用固定指纹的 Mihomo v1.19.34、合成节点和本机 HTTP 源站通过工作区检查。「连接 macOS」提供将非本地请求交给内核的 PAC，即使自定义 PAC 的默认动作设为直连。HTTP 和 SOCKS5 监听可用；内核规则、全局和直连切换无需重新写系统代理设置，端口不变。模式和节点切换读回控制器确认。
- 模拟设置覆盖授权拒绝、恢复前保留监听、自定义 PAC 与「跟随流量模式」互切、系统还在使用旧 URL 时保留已发布的两个地址、系统更新后重试和结束会话时清理。验证没有改写本机实际网络设置，没有访问真实订阅或公网节点。用户浏览器与实际授权提示仍待复测。

## 开发版 · Android 本机代理

- Apple Silicon 上的 Android API 24 ARM64 无窗口模拟器：独立离线包和 Relay 调试包均通过 Instrumentation。Relay 用单独的本机 Mihomo Shadowsocks 服务和 HTTP 源站，仅使用合成凭据。无凭据或错误凭据被拒绝，HTTP 代理认证头没有传到源站；启动检查也验证了 SOCKS5 用户名和密码握手。
- 直连、全局和规则模式均实测实际 HTTP 流量。全局用可用节点经 Shadowsocks 转发，切换到不可用节点无直连回退，规则模式保留回环绕过。换节点和模式保持监听地址不变；停止后端口和私有运行目录清理。
- 两个包应用 ID 独立。构建检查 16 KiB 对齐、调试签名、离线包无权限和 Relay 仅有联网权限。未验收实体设备、API 35 上的生命周期、全设备 VPN、后台常驻或其他协议的 Android 数据面。未发布含 Mihomo 的 Android 包。

## 开发版 · Hysteria2

- Apple Silicon Release 构建、核心测试和便携命令的离线脱敏检查通过。覆盖两种分享链接、Clash YAML／JSON、固定端口、SNI、混淆密码与证书校验字段。
- 使用 Mihomo v1.19.34 在本机回环和合成证书下确认普通、Salamander、Gecko 三种配置能实际转发 HTTP 和 SOCKS 请求；不匹配的证书指纹被拒绝，没有回退到直连。同期五类 VMess／VLESS 回归通过，测试前后系统代理未变化。未访问真实订阅或公网节点。

## 开发版 · macOS 连接修复

- Apple Silicon Release 构建与核心检查通过。使用固定指纹的 Mihomo、本机回环与模拟网络服务，验证了「连接 macOS」冷启动、复用手动会话、授权被拒后保留本机代理，以及停止时先恢复原代理设置，再关闭 PAC 和 Mihomo 监听。单独覆盖了 macOS 恢复状态尚未更新时保留监听和恢复记录。
- 本机预览 App 已构建并校验签名和架构。App 内带 Mihomo 及其许可证；仍须添加自有节点或订阅。前述系统代理检查没有写入实际系统设置，也未使用真实订阅。授权窗口、网络服务切换和浏览器实际读取系统 PAC 仍需桌面验证。
- Build 5 的菜单栏、概览和 PAC 页区分「已配置」和「系统默认已启用」。核心检查模拟系统设置传播延迟和其他工具接管，验证状态会更新且不写代理设置，也不丢失恢复记录。状态只表示 macOS 默认 PAC 的指向；浏览器是否经过代理还要看 PAC 规则和实际连接。

## 0.3.0 · 2026-11-24

- Apple Silicon / macOS 15.7.2：Release 构建和核心检查通过。PAC 预览与 JavaScript 的动作一致；macOS 原生 PAC 解析器验证直连、HTTP/HTTPS 代理与国际化域名。
- 本机 PAC 只服务回环上的随机地址。夹具验证脚本内容、缓存响应头、请求方式、路径和请求头大小限制。应用模型在真实运行的合成内核上提供 PAC，停止时撤下地址和代理监听。
- 系统 PAC 使用模拟网络服务验证选择、备份后写入、原样恢复、尊重外部修改，以及写入、更新或恢复中断后的重试。未实际改写本机网络服务。
- 订阅导入、下载与刷新回归通过；成功刷新和 HTTP 503 失败均不会中断当前代理监听。没有窗口时，应用模型能发现自有内核退出。历史访问目的地不写入磁盘或诊断报告。
- 用 Mihomo v1.19.34 和模拟 Xray 验证五类 VMess/VLESS 转发。上传和下载累计量、测得速率、活动连接详情、关闭单条及全部连接均通过。错误凭据没有回落到直连。测试前后实际 macOS 系统代理状态相同。
- 本机 App 与公开 ZIP 均通过签名检查。解压后复核了 macOS 13.0 部署目标、arm64、版本 0.3.0、SHA-256 和三份许可；ZIP 中没有内核或真实配置。

桌面验收仍需在用户许可下进行：用真实网络服务启用并恢复系统 PAC，检查授权提示和浏览器分流；强制结束内核后从 PAC 页恢复；关闭主窗口并通过菜单栏操作，检查图表的实际呈现。公开安装包使用本机临时签名，未做 Developer ID 签名与公证。

## 0.2.0 · 2026-11-24

新增订阅管理和菜单栏常驻。

- Release 构建通过。
- 10 项核心检查通过，覆盖原有节点导入、订阅解析、Clash/Mihomo JSON 及 YAML 节点映射。YAML 覆盖常见块式与行内写法、略过不兼容节点，以及拒绝含糊或超量的文档。
- 使用合成订阅的本机 HTTP 服务通过下载、更新、错误响应、超量响应及重定向测试。Clash YAML 下载后可导入兼容节点，内嵌的代理提供者地址没有收到请求。未访问真实订阅服务。
- 本地存储检查通过：重读、原子替换快照与清除订阅无误，目录权限为 `0700`，记录文件权限为 `0600`。
- 应用模型使用随包 Mihomo 验证：运行中的回环监听在刷新成功和 HTTP 503 失败后均保持，停止后释放监听并应用最后一次成功更新；重建工作区可读取该缓存。无主窗口时，健康检查仍能发现内核退出并清除代理状态。
- HTTP 和 SOCKS 回环转发回归通过：VMess/TCP、VLESS/TCP、VLESS/WS+TLS、VLESS/gRPC、VLESS/TCP+REALITY/Vision。错误认证被拒绝，停止后监听和临时目录已清理，系统代理状态保持原样。

桌面交互需手动验收：

1. 添加两份格式受支持的订阅，分别刷新；错误响应不应清空上次成功的节点。退出并重开 CLAY，检查订阅和已缓存节点仍在。
2. 启动代理后关闭主窗口，从菜单栏查看代理仍在运行。点「打开 CLAY」应回到同一个会话；再点一次应显示已有窗口，端口保持不变。
3. 代理运行时刷新或移除订阅，现有连接和节点列表应保持；停止后检查已应用的新列表。用菜单栏重新启动，再从菜单栏退出。退出后 CLAY 的代理端口应释放。

## 0.1.0 · 2026-11-23

2026-11-23，Apple Silicon，macOS 15.7.2 / Swift 6.0.3。Mihomo v1.19.34、Xray v26.11.9 均来自固定的官方发布，下载包的 SHA-256 与 GitHub 发布资产摘要一致。交付仅包含 CLAY 与独立的 Mihomo 内核；Xray 是测试工具。

- 构建：Release 成功；CLAY.app 的 Info.plist、arm64 可执行文件和本机签名检查通过。未自动启动桌面界面，未做真人操作验收，未公证。
- 6 项程序化检查通过：VMess 输入、VLESS 输入和不支持的选项、REALITY/Vision 字段、JSON 出站导入、离线订阅和多节点配置。多节点内核标识独立于显示名称。
- 真实流量回环：VMess/TCP、VLESS/TCP、VLESS/WS+TLS、VLESS/gRPC、VLESS/TCP+REALITY/Vision。验证 HTTP 和 SOCKS 的转发时，服务端、测试目标和客户端全部限制在回环，检查随机响应内容一致；通过认证 API 切换节点和测延迟。WS 的自签名测试证书需要显式跳过验证，仅用于夹具。
- 故障和清理：错误的 VLESS UUID 无法取得响应，未因失败回落到直连；停止后代理监听解除，临时目录删除；测试前后系统代理状态一致。合成的 Xray 测试配置只放行回环测试目标的单一端口。
- 本机真实配置最后做只读验收：成功导入一个 VLESS/TCP/REALITY 出站；两个直连或拒绝类出站按预期略过。生成的配置通过 Mihomo 的 test-only 检查。源文件 SHA-256 和系统代理状态一致。没有记录原服务器、UUID、密钥或配置内容，也未连接真实节点。
- 真实公网节点的远端握手、延迟和通过公网传输未验证。

复验环境：使用随包内核和官方 Xray。用真实配置只能先做 verify-config；以用户选择的目标启动实际探测是单独的运行验证。
