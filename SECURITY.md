# 安全问题报告 / Reporting a security issue

如果发现可能泄露订阅地址、节点凭据或流量，或者影响安装包和更新来源的问题，请使用 GitHub 的[私密漏洞报告](https://github.com/henwanla/CLAY/security/advisories/new)。请提供受影响版本和平台、问题的影响及使用合成数据的复现步骤。报告里不要附真实令牌、完整订阅地址、节点配置、连接记录或签名密钥。功能问题可在 Issues 里提交，仍请先移除个人数据。

如果真实凭据已经暴露，请先到签发方撤销并更换，再提交报告。仅删除 GitHub 上的文本或提交无法让已复制的凭据失效。

If you find a way for CLAY to expose subscription URLs, node credentials, or traffic, or to compromise the source of an installer or update, please use [GitHub private vulnerability reporting](https://github.com/henwanla/CLAY/security/advisories/new). Include the affected version and platform, the impact, and steps that reproduce the issue with synthetic data. Leave real tokens, complete subscription URLs, node configurations, connection history, and signing keys out of the report. For ordinary bugs, use Issues with personal information removed.

If a real credential is exposed, revoke and replace it with its issuer before filing the report. Removing the original text or commit cannot invalidate copies.
